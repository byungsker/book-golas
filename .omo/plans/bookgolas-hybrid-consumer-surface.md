# Bookgolas Hybrid Consumer Surface and Native Action Bridge Implementation Plan

> **For Hermes:** Use the subagent-driven-development skill to implement this plan task-by-task. Do not treat this plan as authorization to change production, deploy a hosted service, publish a store build, or create a public PR.

**Goal:** Build one end-to-end Bookgolas product slice in which an admin publishes dynamic content, the Flutter Home surface presents it, a Next.js consumer WebView renders the detail, typed messages invoke real native capabilities, and owner-scoped events are read back without claiming unverified product growth.

**Architecture:** Keep the existing Web 1.1.0 consumer parity line as the foundation. Add a separate content-hub contract and publish/read/event data model; keep the Flutter Home shell responsible for native lifecycle, seen/dismissed state, loading/error/fallback and WebView ownership; keep Next.js responsible for content rendering and server-side contracts; keep the bridge versioned, origin-allowlisted, request-correlated and capability-based. Start with public/read-only content so session handoff is not a prerequisite, then add private content only through a short-lived server exchange.

**Tech Stack:** Flutter 3.x/Dart, `webview_flutter`, `share_plus`, existing Bookgolas scanner/OCR services, iOS/Android deep links and App Group/Quick Actions, Next.js App Router, React, TypeScript, `next-intl`, Supabase SSR/client, Zod 4, Vitest, Playwright, Supabase migrations/RLS.

**Base:** `origin/version/web/1.1.0@52e9c1db19b307200acef66eef73b86122b315d8` (2026-09-16).

**Important current state:**

- The remote Web line already has authenticated consumer routes, contracts, negative fixtures, offline/session boundaries, Web Push registration contracts and browser evidence scripts.
- `web/src/app/[locale]/(consumer)/announcements/page.tsx` is currently a placeholder route.
- `web/docs/native-consumer-surface-inventory.json` lists native-only capabilities including widgets, Siri/App Shortcuts, native push, camera/OCR, share sheet, subscriptions and deep links.
- Flutter already has `webview_flutter`, `share_plus`, `cunning_document_scanner`, `permission_handler`, `google_vision_ocr_service.dart`, App Group/Quick Action/deep-link channels and book-share code.
- The existing `push_announcements` table/history is delivery-oriented. Do not reuse it as the content source of truth without proving that its lifecycle, localization, audience, read/dismiss state and body contract are sufficient.
- Existing offline policy is online-core: no hidden replay queue or silent mutation. Preserve that boundary.

## Product scope and non-goals

### In scope

- Localized content items for announcements, reading challenges, book tips and release notes.
- Admin create/edit/preview/publish/schedule controls.
- Authenticated consumer content list/detail routes.
- Flutter Home first-seen card/modal with versioned read/dismiss state.
- A reusable Flutter WebView shell, not another terms-only screen.
- Versioned WebView bridge with `requestId`, schema version, capability negotiation, timeout, duplicate suppression and fallback.
- Native actions: open native book/reading route, share content, invoke scanner/OCR and return an editable result.
- Owner-scoped content read/dismiss/event writes with RLS and read-back.
- Browser, contract, Flutter and real-device verification.

### Out of scope for this slice

- Location, step count or background execution features added only to imitate Daangn.
- A hidden offline replay queue.
- Raw Supabase access tokens in WebView URLs or bridge messages.
- Replacing `cunning_document_scanner` or the existing OCR service solely for resume value.
- Claiming retention, conversion, adoption or A/B success before real exposure and read-back.
- Android parity claims before an Android device run passes.
- Production deployment, store publication, public launch or subscription changes.

## Data and bridge contracts

### Content item contract

Use a separate product content model. The exact migration timestamp must be generated by Supabase CLI; do not invent a timestamp.

```text
content_items
- id uuid primary key
- slug text unique not null
- kind text check (announcement|challenge|book_tip|release_note)
- locale text check (ko|en)
- title text not null
- summary text not null
- body_markdown text or body_json jsonb not null
- hero_image_url text nullable
- cta_type text nullable (open_native_book|open_native_reading|open_native_scanner|share_content|open_url)
- cta_payload jsonb nullable
- audience text not null default 'all'
- status text check (draft|scheduled|published|archived)
- publish_at timestamptz nullable
- content_version integer not null default 1
- created_by uuid not null
- created_at timestamptz not null
- updated_at timestamptz not null
```

```text
content_reads
- content_id uuid references content_items(id)
- user_id uuid references auth.users(id)
- seen_at timestamptz nullable
- dismissed_at timestamptz nullable
- completed_at timestamptz nullable
- primary key (content_id, user_id)
```

```text
content_events
- id uuid primary key
- content_id uuid references content_items(id)
- user_id uuid nullable
- event_type text check (impression|open|dismiss|cta_click|native_action_started|native_action_succeeded|native_action_failed|complete)
- surface text check (native_home|web_consumer|webview)
- action text nullable
- request_id uuid nullable
- platform text nullable
- failure_code text nullable
- metadata jsonb not null default '{}'
- created_at timestamptz not null
```

Rules:

- RLS must scope private reads/writes to `auth.uid()`; published public content may be read only when `status='published'` and `publish_at <= now()`.
- The server derives caller identity from the session. Do not accept `user_id`, `owner_id` or equivalent caller identity from request bodies.
- `content_reads` writes must be idempotent on `(content_id, user_id)`.
- `content_events` must accept a client request ID and reject or deduplicate repeated writes where the event semantics require it.
- Publish, read, dismiss and event writes must be read back from the exact owner-scoped target before completion is reported.

### Web ↔ Flutter bridge envelope

```json
{
  "schemaVersion": 1,
  "requestId": "uuid",
  "type": "openNativeBook",
  "payload": { "bookId": "uuid", "target": "detail" },
  "source": "bookgolas-content",
  "timestamp": 0
}
```

Web → Flutter action types:

- `closeWebContent`
- `openNativeBook`
- `openNativeReading`
- `openNativeScanner`
- `shareContent`
- `updateNativeProgress`

Flutter → Web event types:

- `nativeReady`
- `nativeCapabilities`
- `themeChanged`
- `localeChanged`
- `authStateChanged` without access tokens
- `nativeActionResult`
- `networkStateChanged`
- `contentContext`

Bridge rules:

- Allowlist the canonical Bookgolas Web origin and reject unknown navigation origins.
- Validate `schemaVersion`, `requestId`, known action type and bounded payload before dispatch.
- Reply with `accepted`, `succeeded`, `cancelled`, `failed` or `unsupported` and a stable error code.
- Time out native actions; do not leave Web content waiting forever.
- Suppress duplicate request IDs and make writes idempotent.
- Buffer events until WebView/native navigation and auth readiness.
- Handle cold start, warm start, app resume, logout, expired session and missing content/book.
- When the bridge is unavailable, preserve read-only Web content and expose a user-facing fallback.

**Step 1: Add a typed bridge controller**

```dart
class WebContentAction {
  final int schemaVersion;
  final String requestId;
  final String type;
  final Map<String, dynamic> payload;

  const WebContentAction({
    required this.schemaVersion,
    required this.requestId,
    required this.type,
    required this.payload,
  });

  factory WebContentAction.fromJson(Map<String, dynamic> json) {
    final type = json['type'];
    final requestId = json['requestId'];
    if (json['schemaVersion'] != 1 || type is! String || requestId is! String) {
      throw const FormatException('Unsupported Web content action');
    }
    final payload = json['payload'];
    if (payload is! Map) throw const FormatException('Invalid Web content payload');
    return WebContentAction(
      schemaVersion: 1,
      requestId: requestId,
      type: type,
      payload: Map<String, dynamic>.from(payload),
    );
  }
}
```
