# Bookgolas native-to-Web parity matrix

Status: frozen discovery ledger for GitHub issue #416. This document owns the route, state, capability, and evidence contract for the consumer Web implementation; it does not claim that the consumer Web surface is shipped.

## Decision lock

- The baseline is `online-core`: authenticated reading flows, reading records, search, recall, calendar, statistics, and account settings must have browser-observable routes and data ownership before a route can be marked complete.
- `full-parity` is a separate gate. It remains blocked until bounded offline behavior, browser storage/sync conflict handling, and cross-surface evidence are approved. The native review note that reading logs may work offline is recorded as a reference, not as an acceptance claim.
- Paid subscriptions remain disabled. `app/lib/config/feature_flags.dart:2-4` sets `paidSubscriptionsEnabled = false` with `defaultValue: false`, so the Web matrix contains no purchase, restore, upgrade, or billing CTA.
- The preserved public `/support` route is not a shipped-equivalence claim for stale subscription copy. Its reconciliation is explicitly `blocked-by-evidence` and deferred to Task 36, which owns the copy update and release QA.
- Existing marketing, legal, and admin routes remain outside the consumer shell. Admin authorization and data boundaries are not widened by this matrix.

## Canonical URL and state rules

1. `{locale}` means `ko` or `en`. The existing Web routing source is `web/src/i18n/routing.ts:3-7`: Korean is the default and uses the as-needed prefix, while English uses `/en`. The ledger uses the placeholder form so the Korean and English route families cannot drift.
2. `/auth/callback` and `/auth/reset-password` are non-localized protocol routes. They may redirect into a localized app route after session handling.
3. `/app`, `/app/library`, `/app/stats`, `/app/calendar`, and `/app/account` are the five canonical shell tabs. Query values such as `surface`, `tab`, `state`, `action`, and `capability` are canonical direct-entry state keys, not alternate route families.
4. `{bookId}` is an opaque route parameter. The server or repository must scope every book lookup and mutation to the authenticated user; user IDs never appear in a URL.
5. A canonical URL appears once in the JSON ledger. A drawer, modal, sheet, or failure state that can be linked or replayed receives its own explicit state URL.
6. A browser equivalent can be a Web API, a browser permission flow, a route, an inline component, or an explicit capability explanation. `unavailable` is a deliberate product disposition, not a missing mapping.

The legacy native route table resolves into the following canonical Web routes: `/` to `/{locale}/app`, `/book-list` to `/{locale}/app`, `/book-detail` to `/{locale}/app/books/{bookId}`, `/reading-start` to `/{locale}/app/books/new`, `/reading-progress` to `/{locale}/app/stats`, and `/calendar` to `/{locale}/app/calendar`. The legacy table is not copied as a second Web route family, so it cannot create duplicate canonical URLs.

## State contract

Every ledger entry carries `states` and `errorStates`. `errorStates` always includes `error`; the additional values identify the failure branch that QA must exercise.

| State | Web disposition | Evidence required |
| --- | --- | --- |
| loading | Inline skeleton or progress region that preserves the route and retry context | Visible loading region and settled state |
| empty | Contextual empty state with the native action or a documented browser alternative | Empty state plus action/no-action proof |
| error | Inline error with retry or recovery path | Forced failure and recovery proof |
| unauthorized | Auth redirect preserving safe return state; never trust a caller user ID | Signed-in and signed-out isolation proof |
| consent-required | Explain consent and stop the operation until accepted | Consent accepted/declined proof |
| quota | Explain the current product limit; no billing while subscriptions are disabled | Limit branch and no-CTA proof |
| offline | Online-core shows a recoverable unavailable state; full-parity stays blocked | Offline/restore proof before any claim |
| validation | Field-level browser validation with localized text | Invalid and corrected input proof |
| permission-denied | Explain browser permission and provide fallback where possible | Denied permission proof |
| unsupported | Explicit browser capability explanation and safe fallback | Unsupported-browser proof |
| conflict | Preserve user input and require an explicit refresh/merge decision | Concurrent mutation proof |
| stale | Show freshness context and offer refresh | Stale data proof |

The checker uses a closed vocabulary. Allowed `states` are `ready`, `loading`, `empty`, `error`, `unauthorized`, `consent-required`, `quota`, `offline`, `validation`, `permission-denied`, `unsupported`, `conflict`, `stale`, `running`, `paused`, and `disabled`. Allowed `errorStates` are `error`, `invalid-credentials`, `email-not-confirmed`, `rate-limit`, `consent-declined`, `already-registered`, `password-too-short`, `invalid-email`, `expired-link`, `invalid-callback`, `replayed-callback`, `password-mismatch`, `network-error`, `external-unavailable`, `invalid-input`, `forbidden`, `not-found`, `invalid-query`, `provider-denied`, `provider-error`, `recommendation-error`, `limit-reached`, `save-failed`, `invalid-date-range`, `invalid-month`, `invalid-page`, `content-unavailable`, `session-expired`, `invalid-nickname`, `resend-rate-limit`, `session-save-failed`, `session-clear-failed`, `update-failed`, `record-not-found`, `not-enough-records`, `not-enough-history`, `not-enough-data`, `history-load-failed`, `copy-failed`, `delete-failed`, `ai-error`, `review-load-failed`, `draft-restore-failed`, `generation-error`, `source-not-found`, `ocr-error`, `initialization-failed`, `render-failed`, `upload-failed`, `permission-denied`, `offline`, `unsupported`, `stale`, `conflict`, `sync-failed`, `server-validation`, `invalid-return`, `invalid-link`, `invalid-url`, and `reauth-required`.
